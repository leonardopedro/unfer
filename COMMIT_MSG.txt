Share the Why3 toolchain with australVM, on why3 1.8.x

Reverses the direction of the previous commit. That one pointed australVM's
Why3 at this repo's channel (nixos-23.05, why3 1.6.0) to get a shared store
path. It worked — both resolved one build — but running the extraction driver
showed 1.6.0 is the wrong version to converge on:

    $ why3 extract -D unfer_ocaml.drv authorize_gate.mlw -o out.ml
    Unknown val bool.Bool.infix =

`lib/why3_plugin/unfer_ocaml.drv` maps `bool.Bool`'s `=`. That operator exists
in Why3 1.8.x and does not exist in 1.6.0's `bool.Bool` (which has only andb,
orb, notb, xorb, implb, ite). So the driver was written against 1.8.x, and
this repo's own channel could not run it — the S36 extraction path was already
broken here, and still exits 0 while failing, which is the same false-success
shape as a missing prover.

Converging on 1.8.2 instead fixes that rather than preserving it:

  before   australVM  nixos-unstable  why3 1.8.2   sglqns…
           unfer      nixos-23.05     why3 1.6.0   wsh74n…
  after    both       nixos-unstable  why3 1.8.2   sglqns…   (one store path)
           both       alt-ergo 2.6.3  jha8y7…              (one store path)

Neither base channel moves: australVM needs nixos-unstable for the cranelift
bridge's glibc, this repo needs 23.05 for CUDA and Haskell. So the toolchain is
pinned by revision on each side — `why3-nixpkgs` here at 34ab990…, which is the
revision australVM's own channel already resolves. Pinned by revision rather than
by branch deliberately: a floating `nixos-unstable` would let the two flakes
drift apart silently the next time the channel advances.

Checked before moving: `prob_kernel/src/whyml.rs` parses prover output by
counting lines containing `Valid` and rejecting on `Invalid`/`Failure`/
`Timeout`, so it does not depend on 1.6-era formatting. Its whyml tests pass
under 1.8.2.

Side benefit: alt-ergo is now 2.6.3, the version Why3 1.8.x expects, so the
"prover version not recognized" warning from the free 2.4.3 build is gone.

Verified: why3 extract on the driver succeeds (388-byte output — the case that
failed on 1.6.0), identical store paths in both repos, unfer_ffi 113 and
prob_kernel 53 tests pass.
